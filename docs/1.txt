# Crowd-Fix Podcasts – פרק 1: יסודות + שמירה ראשונה

ברוכים הבאים לסדרת הפודקאסטים "Crowd-Fix Podcasts"! בסדרה הזו, אנחנו נעבור צעד אחר צעד דרך בניית עורך תמלילים (טקסטים מדוברים) ושרת אחורי (backend) שאני מפתח. נתקדם לאט וביסודיות, כדי שגם אם אתה חדש בתחום הפיתוח, תוכל להבין כל שלב. היום זה פרק 1: נתקין ונריץ את האפליקציה, נסייר במבנה המסך, נגדיר מונחים מרכזיים, נבצע שמירה ראשונה, ונדון במה שקורה מאחורי הקלעים – ברשת (wire) ובמסד הנתונים (database).

אני אסביר הכל בצורה מפורטת, כאילו אני מדבר עם מישהו שמעולם לא כתב קוד אבל רוצה להבין. אם יש מונחים טכניים, אפרק אותם לחלקים קטנים ואסביר למה הם חשובים. נשתמש בפורמט Markdown כדי שיהיה קל להעתיק פקודות – למשל, בלוקים של קוד יהיו מסומנים ככה שתוכל להדביק אותם ישירות למסוף שלך.

## סעיף 1: מה הפרויקט הזה

נתחיל מהבסיס: הפרויקט הזה הוא מאגר קוד (repository, או בקיצור "repo") שמכיל שני חלקים עיקריים. חשבו על repo כתיקייה גדולה שמכילה את כל הקבצים של הפרויקט, ואפשר להוריד אותה מגיטהאב או דומה.

- **החלק הקדמי (frontend editor)**: זה החלק שאתה רואה על המסך – אפליקציה בודדת עמוד (single-page app, או SPA) שמציגה תמלילים ארוכים מאוד במהירות גבוהה, ותומכת בעריכה (שינוי הטקסט), היסטוריית גרסאות (version history), הצגת הבדלים (diff viewing), ואישורים (confirmations). היא ידידותית לכתיבה מימין לשמאל (RTL, כמו בעברית או ערבית), מה שאומר שהטקסט זורם מימין לשמאל בלי בעיות.
  
- **החלק האחורי (backend)**: זה השרת שרץ מאחורי הקלעים. הוא מספק תיקיות/קבצים/פרקים (episodes), שומר תמלילים בגרסאות עם הגנה מפני התנגשויות (hash-gated saves), מייצא תמלילים לפורמטים שונים, ומציע נקודת סיום ליישור (alignment endpoint).

כדי לראות את זה בפעולה, פתח את קובץ README.md בשורש ה-repo. זה קובץ טקסט פשוט שמסביר את הפרויקט. אם אתה חדש, README הוא כמו "מדריך התחלה" לכל פרויקט קוד – תמיד קרא אותו קודם.

**הסבר פינה קטנה**: למה "monorepo"? זה אומר שהכל במאגר אחד, במקום לפצל לפרויקטים נפרדים. זה מקל על ניהול, אבל יכול להיות כבד אם הפרויקט גדל. כאן זה מתאים כי החלקים תלויים זה בזה.

## סעיף 2: איך לנווט בקוד

עכשיו, בוא נלמד איך למצוא דברים בקוד. אם אתה חדש, קוד זה כמו ספר – יש תיקיות (directories) וקבצים. הנה מפה פשוטה:

- **v2/index.html**: זה השלד של האפליקציה – קובץ HTML שמגדיר את המבנה הבסיסי של המסך, כולל התמיכה ב-RTL (כתיבה מימין לשמאל). HTML זה כמו "הבניין" של האתר – הוא קובע איפה הכפתורים והטקסט.
  
- **v2/main.js**: זה הקובץ ש"מדליק" את האפליקציה – מחבר את העורך, הפאנל של הדפדפן (browser panel), כרטיסיות ההיסטוריה וההבדלים, HUD (תצוגת מפתחים), ומקשי מקלדת/ממשק משתמש. JS (JavaScript) זה השפה שגורמת לדברים לזוז.

- **v2/render/overlay.js ו-v2/render/virtualizer.js**: אלה החלקים שמציירים את התמליל במהירות. אנחנו "ווירטואליזציה" (virtualize) את הטקסט – מציירים רק מה שרואים על המסך (ועוד קצת מאגר) כדי שהגלילה תהיה חלקה גם בטקסטים ענקיים. חשבו על זה כמו ספר – אתה לא קורא את כל הספר בבת אחת, רק את העמוד הנוכחי.

- **v2/ui/*.js**: רכיבי ממשק משתמש, כמו כפתורים, נושאים (themes), וחלון מיזוג (merge modal).

- **v2/workers/diff-worker.js ו-v2/workers/diff-core.js**: חישוב הבדלים (diffing) מחוץ לחוט הראשי (off-main-thread) כדי לא להקפיא את המסך. diff-core זה מודול נקי שנבדוק גם לדיוק (determinism).

- **explore/app/routes/*.py**: נקודות הסיום של השרת (endpoints):
  - browser.py: /folders, /files, /episode – לניווט בתיקיות.
  - transcripts.py: שמירה/קריאה/גרסה אחרונה/היסטוריה/מילים/אישורים.
  - export.py: ייצוא ל-VTT/CSV/JSON וקטעי אודיו.
  - auth.py: התחברות ובדיקת פיתוח.

- **explore/app/services/*.py**: כלים למסד נתונים ואינדקסים.

**טיפ למתחילים**: אם אתה רוצה להבין "מה מפעיל תכונה X", חפש קודם ב-explore/app/routes את ה-API (ממשק תכנותי), ואז ב-v2/data ו-v2/main.js כדי לראות איך החלק הקדמי קורא לו. השתמש בחיפוש בקוד (Ctrl+F) כדי למצוא מילים כמו "save" או "diff".

## סעיף 3: הרצה מקומית (Windows PowerShell ובאש)

עכשיו, בוא נריץ את זה במחשב שלך. "הרצה מקומית" פירושו להפעיל את השרת והאפליקציה על המחשב שלך, בלי צורך באינטרנט. נשתמש בסביבה וירטואלית (venv) כדי לבודד את ההתקנות – כמו "חדר נפרד" כדי לא ללכלך את המערכת.

**עבור Windows (PowerShell)**:
1. פתח PowerShell (חפש במחשב).
2. הרץ:
   ```
   .venv/Scripts/Activate.ps1
   ```
   (זה מפעיל את הסביבה הווירטואלית. אם היא לא קיימת, צור אותה קודם עם `python -m venv .venv`.)
3. התקן דרישות:
   ```
   pip install -r explore/requirements.txt
   ```
   (pip זה מנהל חבילות – הוא מוריד ספריות כמו Flask, השרת שלנו.)
4. הרץ את הסקריפט:
   ```
   ./dev.ps1
   ```
   (זה מפעיל את השרת עם ברירות מחדל: DataDir זה ".", כלומר התיקייה הנוכחית, ומצב פיתוח (Dev) מופעל – מה שאומר בלי אימות אמיתי.)

**הסבר פינה קטנה**: אם אתה רוצה לשנות את תיקיית הנתונים: `./dev.ps1 -DataDir C:\data`. לכבות מצב פיתוח: `./dev.ps1 --% --no-dev`. מצב פיתוח עוקף אימות כדי שיהיה קל להתחיל.

**עבור bash (macOS/Linux)**:
1. הרץ:
   ```
   python -m venv .venv && source .venv/bin/activate
   ```
   (יוצר ומפעיל סביבה וירטואלית.)
2. התקן:
   ```
   pip install -r explore/requirements.txt
   ```
3. תן הרשאות:
   ```
   chmod +x dev.sh
   ```
   (chmod משנה הרשאות – עושה את הסקריפט רץ.)
4. הרץ:
   ```
   ./dev.sh
   ```
   (ברירות מחדל: DATA_DIR=".", מצב פיתוח מופעל. לשנות: `./dev.sh -d /path/to/data --no-dev`.)

עכשיו השרת רץ ב-http://localhost:5000. אם אתה חדש, "localhost" זה הכתובת של המחשב שלך.

## סעיף 4: פתיחת העורך (מבנה RTL)

העורך בנוי RTL – מימין לשמאל. זה אומר:
- הפאנל של הדפדפן (תיקיות/קבצים) מימין.
- העורך עצמו באמצע.
- פאנל ההבדלים/היסטוריה משמאל.

פתח: v2/index.html (כקובץ מקומי – file:// URL). האפליקציה תחבר אוטומטית ל-http://localhost:5000. לחילופין, פתח http://localhost:5000/v2 (השרת מגיש את הקבצים הסטטיים).

**הסבר פינה קטנה**: RTL זה חשוב לשפות כמו עברית – הטקסט מתחיל מימין. אם אתה רואה בעיות, בדוק שהדפדפן תומך (כרום/פיירפוקס טובים).

## סעיף 5: מונחים מרכזיים (מוסברים בפשטות)

- **טוקנים (Tokens)**: התמליל מיוצג כרצף של "טוקנים" – כל טוקן זה מילה או תו בודד, בתוספת מידע זמן (מתחיל/מסיים). טוקן מיוחד "\n" מסמן הפסקת פסקה (segment break). למה? כדי שיהיה קל לנתח ולערוך.

- **רינדור ווירטואלי (Virtualized rendering)**: במקום לצייר את כל הטקסט ב-DOM (המודל של הדף), מציירים רק חלון + מאגר. זה שומר על חלקות בגלילה.

- **טקסט בסיס (Baseline text)**: כשטוענים פרק, זה הטקסט ההתחלתי להשוואה. בעריכה, עוקבים אחר שינויים מהבסיס לטקסט הנוכחי.

- **HUD**: תצוגת מפתחים (toggle עם Ctrl+Alt+D). מראה טוקנים גלויים/סה"כ וזמן רינדור אחרון. שימושי לבדיקת ביצועים.

**על המסך**: לחץ Ctrl+Alt+D, הצבע על ערכי HUD.

## סעיף 6: טעינת פרק

על המסך: לחץ תיקייה בפאנל ימין, אז קובץ. האפליקציה קוראת /episode, שמחזיר JSON עם תמליל בסיס ואודיו URL. האודיו מוגש דרך /audio. הטקסט מוצג כטוקנים, עם "\n" בין פסקאות.

## סעיף 7: עריכה ראשונה + שמירה (כולל מקרי קצה)

עריכה קטנה: לחץ בתמליל, הקלד "!". שמירות הן גרסאות עם הגנה (hash-gated). האפליקציה שולחת POST ל-/transcripts/save עם doc, parentVersion, expected_base_sha256, text, words.

**מקרה קצה**: שמירה ראשונה – parentVersion null, expected_base_sha256 ריק. השרת יוצר גרסה 1 ומחשב hash.

על המסך: לחץ “⬆️ שמור תיקון”. התג הגרסה מתעדכן.

**דוגמה מדויקת (fetch)**:
```
fetch('http://localhost:5000/transcripts/save', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  credentials: 'include',
  body: JSON.stringify({
    doc: 'אבות האומה/2024.08.22 צריך לדעת מי להתגרש, טו באב וחנן בן ארי #13.opus',
    parentVersion: null,
    expected_base_sha256: '',
    text: '...your edited full text here...',
    words: [
      { "word": "hello", "start": 0.0, "end": 0.4, "probability": 0.95 },
      { "word": " ", "start": 0.4, "end": 0.5, "probability": 0.99 },
      { "word": "\n" },
      { "word": "world", "start": 0.6, "end": 1.0, "probability": 0.90 }
    ]
  })
}).then(r => r.json()).then(console.log)
```

מחזיר { version: 1, base_sha256: "<hash>" }.

## סעיף 8: איך מחשבים hashes ומדוע מתרחשות התנגשויות

השרת מחשב sha256(text). החלק הקדמי שולח hash צפוי של ההורה. אם שונה – התנגשות. סיבות: שמירה אחרת בינתיים, hash שגוי, הבדלי קידוד (אנחנו מנרמל שורות ורווחים).

## סעיף 9: דמו התנגשות (409) עם דוגמה

סימולציה: שמור שינוי שרת, נסה לשמור ישן – 409 עם reason, latest, parent, diffs.

**קוד להכנה**:
```
(async () => {
  const doc = 'אבות האומה/2024.08.22 צריך לדעת מי להתגרש, טו באב וחנן בן ארי #13.opus';
  const latest = await (await fetch(`http://localhost:5000/transcripts/latest?doc=${encodeURIComponent(doc)}`, { credentials: 'include' })).json();
  const baseHash = latest.base_sha256 || '';
  const newText = (latest.text || '') + ' server edit';
  const saveResp = await fetch('http://localhost:5000/transcripts/save', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    credentials: 'include',
    body: JSON.stringify({
      doc, parentVersion: latest.version, expected_base_sha256: baseHash,
      text: newText, words: [{ word: newText }]
    })
  });
  console.log('server-side save', saveResp.status);
})();
```

עריכות לא חופפות – מיזוג אוטומטי.

## סעיף 10: אישורים (בחירה → שמירה → טעינה מחדש)

אישורים מסמנים קטעים אמינים. אם עריכות לא שמורות – שומר קודם. קורא /transcripts/confirmations/save עם doc, version, base_sha256, items.

**דוגמה**:
```
fetch('http://localhost:5000/transcripts/confirmations/save', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  credentials: 'include',
  body: JSON.stringify({
    doc: 'אבות האומה/...',
    version: 2,
    base_sha256: 'your_version_hash_here',
    items: [
      { start_offset: 10, end_offset: 25, prefix: '...', exact: 'your text', suffix: '...' }
    ]
  })
}).then(r => r.json()).then(console.log)
```

אחרי שמירה, טוען מחדש.
